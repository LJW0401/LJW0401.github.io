1. 关于 AI 提效的还在思考中，周末又有了新的想法，先用 project-workflows 的主 skills 走 requirements → architecture → development-plan → execute 的开发路径从大的最根本的需求出发搭建一个完善的骨架，然后在用旁路 skills quick-feature 逐个添加新的功能，bug-fix 修复遇到的bug。这样会不比直接用主开发路径完成大型项目效果更好？因为完整项目在 requirements-discuss 阶段生成的需求文档总是又臭又长，细节过于丰富，难以快速抓到需求的核心要点，最后的结果总是会有比较大的偏差。而每个小feature的添加则是清晰的，相对而言比较好把握的。基于这个思路可以开始考虑新工具 Todo Agent 的开发了。
2. 又或者说可以考虑再加入一个需求拆解的 skill 帮助拆解需求，实现开发从广度到深度的逐步收敛。也或许是一个比较好的方案？
