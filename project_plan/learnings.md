## 2026-08-25

### Bug 修复：文档侧边栏视图与筛选链接无效
- **发现于**：用户报告
- **现象**：在静态文档页点击目录、标签、归档或具体标签后，URL 查询参数变化，但页面仍显示全部文档。
- **根因**：源站依赖服务端读取 `view` / `tag` / `year` 查询参数并渲染不同 HTML，导出到 GitHub Pages 时只保留了默认列表 HTML，且没有对应的客户端渲染逻辑。
- **修复**：新增静态站客户端视图解析与渲染，复刻源站的目录树、标签卡片、年/月归档折叠和文档筛选，并同步侧边栏选中态。
- **回归测试**：`tests/docs-sidebar.test.mjs` 中的查询参数视图切换、分组层级和页面模块接入用例。
- **为什么原测试没覆盖**：仓库原先没有测试框架或静态导出后的查询参数导航用例，导出验收只检查了页面和链接存在，未检查点击后的可观测内容变化。
- **紧急程度**：中
- **衍生改进建议**：后续每次从服务端导出静态站时，都应把依赖查询参数的页面纳入真实浏览器冒烟测试。

### 快速功能：侧边栏统计自动生成
- **类型**：架构洞察
- **描述**：文章列表和侧边栏原本同时保存总数、标签数和归档数，两份数据在文章增删后容易不一致。
- **建议处理方式**：继续以文章节点的日期、标签和 `data-category` 为单一数据源，侧边栏和各聚合视图只消费计算结果。
- **紧急程度**：低

### Bug 修复：多标签交集筛选与视图保留
- **发现于**：用户对照源站交互后报告
- **现象**：同时选择多个标签时只有第一个生效，且从标签视图点击侧边栏标签会丢失当前视图。
- **根因**：参数解析使用 `URLSearchParams.get('tag')` 将标签误建模为单值，标签链接又从空查询串重建，没有基于当前 URL 做增删。
- **修复**：改用 `getAll('tag')` 做 AND 交集筛选，标签链接基于当前查询参数切换，并在侧边栏与标签卡片中同步多选高亮。
- **回归测试**：`tests/docs-sidebar.test.mjs` 中的“多个标签使用交集筛选”和“标签切换保留当前视图”用例。
- **为什么原测试没覆盖**：原回归测试只覆盖单个 `tag` 参数，未把重复查询键和视图参数共存列为导航边界场景。
- **紧急程度**：中
- **衍生改进建议**：无。
